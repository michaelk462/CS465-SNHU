# CS465-SNHU
## Architecture
### Compare and contrast the types of frontend development you used in your full-stack project, including Express, HTML, JavaScript, and the single-page application (SPA).
The customer site is built on Express with HBS templating, whereas the server responds to each request with complete HTML pages, similar to a traditional multi-page app (MPA). The admin panel is an Angular SPA, loaded once from the server, then independently calling the API endpoint over XHR and slotting components in and out with the router, without reloads. The MPA must optimize for a quick initial load and search the SPA to ensure a smooth user experience.
### Why did the backend use a NoSQL MongoDB database?
I selected MongoDB because of the flexible document model it’s designed around. This kind of data (travel packages) does not fit neatly into a static relational table. With MongoDB, the data is stored as BSON (Binary JSON), and the whole stack is JavaScript, so data encoded in the database passes directly into the Ajax frontend from my server without any translation. Mongoose ODM gives us schema validation and a nice query language.
## Functionality
### How is JSON different from JavaScript, and how does JSON tie together the frontend and backend development pieces? 
JavaScript is a complete programming language. JSON is a minimalist data interchange format that is a detachment of JavaScript object syntax, with no functions or comments, and every key quoted. JSON is the unifying language of the whole stack; Mongoose serializes MongoDB documents into JSON, Express delivers them over the wire with res.json(), and Angular turns them back into typed Trip objects using HttpClient. It’s the same structure in the database, across the API, and into the Angular component; it is not translated at any boundary.
### Provide instances in the full stack process when you refactored code to improve functionality and efficiencies, and name the benefits that come from reusable user interface (UI) components. 
The biggest refactoring was the conversion of static HTML pages to Handlebars templates to populate JSON data dynamically from the server, reducing duplication of markup. Meanwhile, on the Angular side, “TripCardComponent,” “TripListingComponent,” “AddTripComponent,” and “EditTripComponent” are each given one responsibility. No changes won’t affect the rest of the app. Finally, I collected all API calls in “TripDataService” and all JWT handling in “AuthenticationService” so those bits of logic can be maintained and tested in one place.
## Testing
### Methods for request and retrieval necessitate various types of API testing of endpoints, in addition to the difficulties of testing with added layers of security. Explain your understanding of methods, endpoints, and security in a full-stack application. 
The Express API maps HTTP methods to CRUD routes at endpoints such as GET /api/trips, POST /api/trips, PUT /api/trips/:tripCode, POST /api/login, and POST /api/register. Testing each endpoint involves ensuring correct status codes and response shape both on valid input, as well as on errors. The JWT authentication scheme adds additional complexity; protected routes require the presence of an Authorization header with the value ‘Bearer;’ the tests need to use /api/login to get a token before trying to call secure routes. In Angular, the Jasmine/Karma spec files use the HttpClientTestingModule to ‘fake’ API responses and the AuthenticationService to simulate the logged-in state.
